# Privacy and Synthetic Data Boundary

This repository is a public portfolio artifact. It is intended to show Azure SQL Database administration practice without exposing private systems, private accounts, or real attendance data.

## Core rule

The repository contains only synthetic data, reproducible lab code, public-safe documentation, and summarized verification results created for this independent project.

## Permitted public content

- Synthetic people, offices, devices, access points, and attendance events
- Reserved example domains such as `example.com`
- Generic architecture and relational models
- Reproducible SQL and generator code
- Summarized query-plan and performance measurements
- Generic resource naming examples

## Excluded content

- Passwords, keys, tokens, connection strings, or `.env` files
- Subscription IDs, tenant IDs, billing IDs, or personal IP addresses
- Unredacted portal screenshots
- Personal Azure SQL server names when they identify the account
- Real people, emails, device identifiers, offices, or attendance records
- Employer names, systems, code, field names, schedules, or architecture
- Terraform state, BACPAC files, database backups, or raw audit exports
- Tableau workbook binaries, packaged extracts, or private connection metadata

## Portfolio statement

> This independent Azure SQL lab models a common aggregate attendance-estimation problem: badge-access data can provide an incomplete estimate in shared-entry situations. The Azure implementation uses entirely synthetic data and independent lab assets. It does not reproduce, connect to, or disclose any employer system, dataset, identity, credential, internal identifier, code, screenshot, field name, schedule, or proprietary architecture.
